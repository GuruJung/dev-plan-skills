# 한영 README와 사용자 중심 문서 구조

## 요약

GitHub 기본 문서인 `README.md`를 영문으로 제공하고, 의미와 강도가 같은 한글 대응본을 `README-ko.md`로 제공한다. 두 문서는 설치·사용자를 우선하는 동일한 구조를 유지한다.

## 요구사항과 제외 사항

- 현재 한글 `README.md`를 `README-ko.md`로 옮기고, 이를 충실히 번역한 영문 `README.md`를 만든다.
- 두 문서 상단에 상대 언어 문서로 이동하는 링크를 둔다.
- 두 문서는 다음 순서를 공유한다.
  1. 프로젝트 개요와 제공 기능
  2. 설치 및 설치 확인
  3. 빠른 시작과 권장 자동 흐름
  4. 세 스킬의 역할, 수동 저장·구현과 실행 경계
  5. 업데이트·제거·복원
  6. 스킬 작성·동기화·개선 등 유지보수자 안내
- 기존 README의 실질적인 정보는 삭제하지 않고 사용자용 내용을 위로, 유지보수 상세를 아래로 재배치한다.
- 명령, 경로, 스킬명, mode 값, 환경변수와 코드 예제는 두 문서에서 동일하게 유지한다.
- 향후 두 README 중 먼저 수정된 문서를 해당 작업의 원본으로 삼고 다른 언어 문서를 같은 의미와 강도로 갱신한다. 고정 원본은 두지 않는다.
- 상태나 mtime으로 원본을 안전하게 정할 수 없으면 임의로 선택하지 않고 사용자 결정을 받는다.
- 체크섬 상태나 전용 record/check 스크립트는 추가하지 않는다. 구조·언어·핵심 계약 테스트와 독립 리뷰로 동등성을 보호한다.
- 스킬 동작, 호출 계약, 설치 산출물과 공개 명령은 변경하지 않는다.
- 별도 한·영 `CONTRIBUTING` 문서나 추가 언어 문서는 만들지 않는다.

## Current Spec Impact

- `replace`: 기존 단일 README 사용자 문서 의도를 다음 현재 의도로 교체한다.
  - `README.md`는 영문 기본 문서이고 `README-ko.md`는 한글 대응본이다.
  - 두 문서는 의미와 강도, 사용자 흐름과 실행 경계를 동일하게 유지한다.
  - 설치·빠른 시작·사용법을 유지보수 상세보다 먼저 제공한다.
  - 고정 언어 원본 없이 안전하게 선정된 수정본을 기준으로 대응본을 동기화한다.
- 기존 워크플로 의도와 한글 current-spec 서술을 보존하고 새 기능 명세를 결정 근거에 연결한다.

## 사용자 결정 사항

| 주제 | 사용자 결정 | 이유·tradeoff | 적용 범위 |
|---|---|---|---|
| 기본 README 언어 | `README.md`는 영문, `README-ko.md`는 한글로 제공한다. | GitHub에서는 다양한 언어의 사용자가 문서를 보기 때문이다. | 저장소 사용자 문서 |
| 번역 동등성 | 두 문서는 어느 시점이든 의미가 동일해야 한다. | 별도 이유는 제시하지 않았다. | README 전체 |
| 주요 독자 | 스킬을 설치해 사용하는 독자를 우선한다. | 별도 이유는 제시하지 않았다. | 문서 구성과 순서 |
| 기존 상세 내용 | 유지보수자용 내용을 삭제하지 않고 하단에 모두 유지한다. | 별도 이유는 제시하지 않았다. | README 유지보수 절 |
| 편집 원본 | 고정 원본을 두지 않고 먼저 수정된 언어를 원본으로 삼는다. | 별도 이유는 제시하지 않았다. | 향후 README 수정 |
| 동기화 보호 | 별도 체크섬 없이 지침과 테스트로 보호한다. | 별도 이유는 제시하지 않았다. | README 동기화 검증 |

## 승인 기준

- GitHub에서 `README.md`가 완전한 영문 사용자 문서로 표시되고 한글 문서 링크가 즉시 보인다.
- `README-ko.md`가 같은 정보, 순서, 명령과 제약을 자연스러운 한글로 제공한다.
- 설치와 첫 사용 방법이 내부 개발·복구 설명보다 먼저 노출된다.
- 두 문서를 절별로 대조했을 때 의미 누락이나 강도 차이가 없다.
- 한쪽 문서만 있거나 핵심 계약·구조가 어긋나면 테스트가 실패한다.
- 모든 eval이 통과하고 독립 리뷰에서 P0–P2 finding이 없다.
