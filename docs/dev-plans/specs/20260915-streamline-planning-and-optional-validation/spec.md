### 요약과 요구사항

기본 Plan 모드가 이미 제공하는 조사·인터뷰·변경 금지 설명을 줄이고, 프로젝트 고유의 명세 관리와 실행 계약에 집중한다. eval·smoke 계약은 필요한 기능에만 만들며, 내장 리뷰의 실질적인 판단 기준을 계획 수립에 반영한다.

- `create-dev-plan`의 첫 번째 파일 쓰기·branch 생성·구현 금지 문단을 삭제한다. 계획 중 허용되는 행동은 활성 Plan 모드의 규칙을 따른다.
- 일반적인 저장소 조사, 질문 절차, 표준 인터뷰 항목의 반복을 기본 Plan 모드에 위임한다. 명시적 스킬 호출 및 Plan 모드 진입 조건은 유지한다.
- 지속 명세와 로컬 계획의 분리, current spec의 coverage, 사용자 결정 기록, feature ID, 저장·구현 인계 등 프로젝트 고유 계약은 유지한다.
- eval과 smoke의 필요성은 각각 판단한다. 적용되는 저장소 필수 검사, 변경의 실제 위험, 실행 가능한 검증의 유용성을 기준으로 에이전트가 결정하고 계획에 짧게 기록한다. 중요한 불확실성만 사용자에게 질문한다.
- 별도 eval 계약이 없어도 의미 중심 승인 기준과 적절한 검증 방법은 남긴다. 수동·의미 검토로 충분한 작업에 형식적인 실행 명령을 만들지 않는다.
- 계약을 생략했다고 저장소 필수 검사나 발견된 결함을 무시하지 않는다. 실행 실패나 환경 부족을 단순히 “불필요”로 바꾸어 통과시키지 않는다.
- smoke가 불필요한 기능은 적용되는 검증과 독립 리뷰를 통과하면 통합·완료한다. 추가 사용자 확인을 강제하지 않는다.
- 목표 루프의 목표·guardrail 측정과 예산·checkpoint 계약은 유지한다. 별도의 최종 eval과 통합 후 smoke는 필요성을 따로 판단한다.
- 계획에서 정확성·보안·성능·유지보수성, 기존 동작의 회귀, 관련 호출부와 경계 사례, 적용되는 프로젝트 리뷰 규칙을 고려한다. 이번 작업에 관련된 제약·불변조건·위험만 승인 기준과 검증 방법에 반영한다.
- 리뷰 결과의 JSON 형식, finding 작성법, 우선순위 표기 규칙을 매 계획에 복사하지 않는다. 실제 구현 후 독립 리뷰는 계획의 체크리스트에 한정하지 않는다.

네이티브 worktree 도입, 독립 reviewer를 `/review` 호출로 교체하는 작업, 저장·통합 승인 범위의 변경은 포함하지 않는다.

### Current Spec Impact

`docs/dev-plans/current-spec.md`의 워크플로와 산출물 설명을 다음과 같이 변경한다.

- **추가:** 일반 계획 절차는 native Plan 모드에 위임하고, 프로젝트별 리뷰 제약을 계획에 반영한다.
- **추가:** eval·smoke의 필요성을 각각 판단하며, 계약이 없는 경우에도 승인 기준과 독립 리뷰를 유지한다.
- **교체:** 로컬 계획 정리 시점을 “통합 smoke 성공 후”에서 “통합 및 적용되는 사후 검증의 성공을 완료 marker로 기록한 후”로 바꾼다.
- 기존 coverage, 명세 분리, 로컬 squash 통합, 복구, 자동 push 금지의 의미와 한국어 서술을 보존하고 이번 기능 명세를 결정 근거로 연결한다.

### 사용자 결정 사항

| 주제 | 사용자 선택 | 이유·tradeoff | 적용 범위 |
|---|---|---|---|
| 중복 문구 | native 기능에 포함된 설명 정리 | 중복 언급이 불필요함 | dev-plan 스킬 |
| 계획 중 쓰기 금지 | 해당 문구 삭제 | Plan 모드의 기본 행동으로 충분함 | create-dev-plan |
| 평가·smoke 계약 | 필요한 경우에만 생성 | 모든 작업에 의무화하지 않음 | 계획·저장·구현·통합 |
| 필요성 판단 | 에이전트가 판단하고 중요한 경우만 질문 | 별도 이유는 명시되지 않음 | 신규 계획 |
| smoke 없는 완료 | 적용되는 검증과 독립 리뷰 후 통합 | 별도 이유는 명시되지 않음 | smoke 불필요 기능 |
| 리뷰 준비 | 내장 리뷰의 요구사항을 계획에 반영 | 별도 이유는 명시되지 않음 | 계획 수립 |

### 승인 기준

- 기본 조사·인터뷰와 파일 쓰기 금지를 반복하지 않으면서 프로젝트 고유 계약은 보존된다.
- eval·smoke 각각의 필요성에 따라 계획을 저장하고 구현·리뷰·통합할 수 있다.
- 불필요한 계약은 생략할 수 있지만 필수 검사의 실패·미실행을 성공으로 기록하지 않는다.
- smoke 없는 통합도 완료 기록과 중단 후 복구를 지원하며, 기존 필수 smoke를 복구 중 생략할 수 없다.
- 계획에 관련된 리뷰 판단 근거가 반영되고, 실제 reviewer는 전체 변경을 독립적으로 검토한다.
- 한·영 문서의 의미와 강도가 같고 설치용 산출물은 영어 ASCII를 유지한다.
